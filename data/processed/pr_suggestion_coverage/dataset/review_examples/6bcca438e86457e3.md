+

+	 sort | uniq -c | sed -e '/^[ 	]*1[ 	]/d')" || {
+	echo >&2 Duplicate Signed-off-by lines.
+	exit 1
+}
+
+commit_check_reg="\[INTERNAL\]|\[PIPELINE3.*?\]|\[INT\]|\[HDB.*?\]|feat\(.*?\)|chore\(.*?\)|fix\(.*?\)|\[HC.*?\]"
+commit_message=$(cat "$1")
+echo "$commit_message"
+commit_check_result=$(echo "$commit_message" | grep -E "$commit_check_reg")
+
+echo "$commit_check_result"
+
+if [ "$commit_check_result" = "" ]; then
+    echo ""
+    echo "**************not meet the specifications****************************************************"
+    echo "*Commit message should contain one of the following format:                                 *"
+    echo "*[<Jira-ID|HC0*-ID>|INTERNAL|INT|chore:|feat(JIRA-ID):|fix(JIRA-ID):] My Pull Request Title *"
+    echo "*example: [PIPELINE3-1234] : Add new feature                                               *"
+    echo "*********************************************************************************************"
+    exit 1
+fi

+# Pre-commit hooks
+
+Code quality checks run automatically on every `git commit`. To activate them locally after cloning:
+
+```bash
+# If you don't have a virtualenv yet:
+uv venv
+
+# Otherwise start here:
+uv pip install -e ".[dev]"
+pre-commit install
+pre-commit install --hook-type commit-msg
+```
+
+Two install commands are needed — `pre-commit install` sets up the code quality hooks, `--hook-type commit-msg` sets up the commit message validator. Both are required.
+
+All hooks use `language: system` — they run from your active virtualenv, which must be activated before committing. The dev install covers every tool (`pylint`, `mypy`, `ruff`, `pydocstyle`, `pytest-cov`, and the formatters).
+
+---
+
+### Quick reference
+
+Every `git commit` runs these hooks in order:
+
+```
+trailing-whitespace     end-of-file-fixer       check-yaml
+pretty-format-yaml      check-toml              pretty-format-toml
+check-merge-conflict    check-added-large-files debug-statements
+ruff                    ruff-format             pylint
+pydocstyle              mypy                    pytest-coverage
+```
+
+`commit-msg` runs separately at the commit-msg stage (validates the message, not the code).
+
+---
+
+### Running hooks manually
+
+Run all hooks against all files:
+```bash
+pre-commit run --all-files
+```
+
+Run a single hook against all files:
+```bash
+pre-commit run <hook-id> --all-files
+# examples:
+pre-commit run pylint --all-files
+pre-commit run mypy --all-files
+pre-commit run pytest-coverage --all-files
+```
+
+Run a single hook against specific files:
+```bash
+pre-commit run <hook-id> --files path/to/file.py
+```
+
+---
+
+### Hooks
+
+#### File hygiene
+| Hook | Covers | Auto-fixes |
+|------|--------|-----------|
+| `trailing-whitespace` | All text files | Yes |
+| `end-of-file-fixer` | All text files | Yes |
+| `check-merge-conflict` | All files | No — blocks commit |
+| `check-added-large-files` | All files >1 MB | No — blocks commit |
+| `debug-statements` | Python — `pdb`, `breakpoint()` | No — blocks commit |
+
+`check-merge-conflict` only activates during an actual `git merge` — it does not fire on normal commits.
+
+#### YAML / TOML
+| Hook | Covers | Auto-fixes |
+|------|--------|-----------|
+| `check-yaml` | All `.yaml` files except `chart/` | No |
+| `pretty-format-yaml` | `.pre-commit-config.yaml` only | Yes |
+| `check-toml` | All `.toml` files | No |
+| `pretty-format-toml` | `pyproject.toml` only | Yes |
+
+`chart/` is excluded from `check-yaml` because Helm templates use `{{ }}` syntax which is not valid YAML.
+
+`pretty-format-yaml` and `pretty-format-toml` are scoped to the project config files only — not every YAML/TOML in the repo.
+
+#### Python quality
+| Hook | Covers | Excludes | Auto-fixes |
+|------|--------|---------|-----------|
+| `ruff` | All Python | — | Yes (lint + import sort) |
+| `ruff-format` | All Python | — | Yes (formatting) |
+| `pylint` | All Python | `db/migrations/versions/` | No |
+| `pydocstyle` | `fl_control_plane/` only | — | No |
+| `mypy` | `fl_control_plane/` only | — | No |
+
+`db/migrations/versions/` is excluded from `pylint` because alembic auto-generates those files with conventions that cannot be changed (digit-prefixed filenames, lowercase variable names like `revision` and `down_revision`).
+
+`pydocstyle` and `mypy` run on production code only — not tests.
+
+`ruff` replaces `flake8`, `isort`, and `black` from the old project — one tool, same coverage.
+
+#### Testing
+| Hook | Covers | Threshold |
+|------|--------|-----------|
+| `pytest-coverage` | Full test suite | configurable (currently 90%) |
+
+Branch coverage is enabled (`branch = true` in `[tool.coverage.run]` in `pyproject.toml`) — both sides of every `if` must be tested, not just the line. This is stricter than line coverage.
+
+**To change the coverage threshold:** edit `--cov-fail-under=<N>` in `.pre-commit-config.yaml` under the `pytest-coverage` hook args.
+
+#### Commit message
+| Hook | Stage |
+|------|-------|
+| `commit-msg` | `commit-msg` (not `pre-commit`) |
+
+Validates format on every commit. Accepted patterns:
+```
+[INT] Description
+[INTERNAL] Description
+[PIPELINE3-1234] Description
+[HDB-123] Description
+feat(JIRA-ID): Description
+fix(JIRA-ID): Description
+chore(scope): Description
+```
+
+The script lives in `.githooks/commit-msg`.
+
+---
+
+### Tool configuration in `pyproject.toml`
+
+All tool settings live in `pyproject.toml` — no separate `.pylintrc`, `.flake8`, or `mypy.ini` files.
+
+Key non-obvious settings:
+
+- **`[tool.pylint.main]` `extension-pkg-allow-list = ["pydantic"]`** — lets pylint load pydantic's C extensions. Without this, pylint produces false positives on pydantic models.
+- **`[tool.pylint.typecheck]` `generated-members`** — suppresses `no-member` errors on `alembic.context` and `alembic.op`. These objects assign their methods dynamically at runtime; pylint cannot see them statically.
+- **`[tool.pylint.messages_control]` `disable = ["redefined-outer-name"]`** — pytest fixtures intentionally shadow outer-scope names. This is a false positive across all test files.
+- **`[tool.pylint.design]` `min-public-methods = 0`** — SQLAlchemy ORM models are intentionally data-only classes with no methods.
+- **`[tool.mypy]` `strict = true`** — enables all mypy checks including missing annotations and untyped calls. SQLAlchemy is excluded via `[[tool.mypy.overrides]]` because its mypy plugin has version compatibility issues.
+- **`[tool.pydocstyle]` `convention = "google"`** — enforces Google-style docstrings, matching the project style guide in `CLAUDE.md`.
+- **`[tool.coverage.run]` `branch = true`** — measures branch coverage. `[tool.coverage.report]` `exclude_also` excludes abstract methods, `raise NotImplementedError`, and `if __name__ == "__main__"` from coverage counts.
+
+---
+
+### Adding or removing hooks
+
+All hooks are in `.pre-commit-config.yaml` under `repo: local` with `language: system`. To add a hook:
+1. Add the tool to `[project.optional-dependencies] dev` in `pyproject.toml`
+2. Run `uv pip install -e ".[dev]"` (or `pip install -e ".[dev]"`)
+3. Add the hook entry to `.pre-commit-config.yaml`
+4. Run `pre-commit run <hook-id> --all-files` to verify
+
+To remove a hook: delete the entry from `.pre-commit-config.yaml` and remove the tool from dev dependencies.
+
+---
+
+### Troubleshooting
+
+**`Executable not found`**
+
+The venv is not activated. Run `source .venv/bin/activate` first.
+
+**`pre-commit install` fails with "Cowardly refusing to install hooks with core.hooksPath set"**
+
+```bash
+git config --list | grep hookspath
+```
+
+If it points to `.git/hooks`, remove it:
+
+```bash
+git config --local --unset-all core.hooksPath
+```
+
+If it points to a different directory, it may be a company-wide hooks setup — do not unset without checking first.
