+description: "Enable or disable CI/CD deployment on a feature branch — modifies workflow triggers, pipeline config, ensures namespace exists, waits for pods, and can revert all changes"
+argument-hint: "[enable|disable] [--branch <name>] [--namespace <name>] [--kubeconfig <path>]"

+
+<objective>
+Toggle CI/CD deployment for a feature branch. When enabling: adds the branch to workflow triggers, sets the productive branch in pipeline config, ensures the target namespace exists on the cluster, commits and pushes, then waits for pods. When disabling: reverts all CI/CD config changes back to main-only and commits.
+
+This skill is project-agnostic — it discovers workflow files, pipeline config, and cluster details at runtime and asks for anything it cannot derive.
+</objective>
+
+<parameters>
+Parse $ARGUMENTS for:
+
+- **action**: `enable` or `disable`. If not provided, ask.
+- **--branch**: Branch name to add/remove from triggers. Default: current git branch.
+- **--namespace**: Kubernetes namespace for deployment. If not provided and enabling, ask.
+- **--kubeconfig**: Path to kubeconfig file. Discovered automatically (see Phase 1).
+
+If `disable` is specified, no namespace or kubeconfig is needed — it only reverts file changes.
+</parameters>
+
+<process>
+
+## PHASE 0 — Discovery
+
+### 0a. Resolve action and branch
+
+```bash
+REPO_ROOT=$(git rev-parse --show-toplevel)
+CURRENT_BRANCH=$(git branch --show-current)
+```
+
+- If action not in arguments, ask: "Enable or disable CI/CD deployment?"
+- If branch not in arguments, default to `$CURRENT_BRANCH`. Confirm with user: "Using branch `$CURRENT_BRANCH` — correct?"
+
+### 0b. Discover workflow files
+
+Find all GitHub Actions workflow files that have a `push.branches` trigger:
+```bash
+find "$REPO_ROOT/.github/workflows" -name "*.yml" -o -name "*.yaml" | \
+  xargs grep -l "branches" 2>/dev/null
+```
+
+Present the list to the user and ask which ones to modify (default: all of them).
+
+### 0c. Discover pipeline config
+
+Look for pipeline configuration that contains a `productiveBranch` setting:
+```bash
+find "$REPO_ROOT/.pipeline" -name "*.yml" -o -name "*.yaml" | \
+  xargs grep -l "productiveBranch" 2>/dev/null
+```
+
+Also check for a `namespace` field in the same file(s):
+```bash
+grep -n "namespace:" "$PIPELINE_CONFIG" 2>/dev/null
+```
+
+If no pipeline config is found, skip this step and inform the user.
+
+## PHASE 1 — Enable
+
+Skip to PHASE 2 if action is `disable`.
+
+### 1a. Resolve namespace
+
+If `--namespace` not provided:
+1. Read the current namespace value from the pipeline config (if it exists).
+2. Ask: "Which namespace should CI/CD deploy to? Current value: `<current>`"
+
+### 1b. Resolve kubeconfig
+
+Priority order:
+1. `--kubeconfig` argument
+2. `$KUBECONFIG` environment variable
+3. Glob for `kubeconfig*.yaml` in `$REPO_ROOT`
+4. Default `~/.kube/config`
+5. Ask the user
+
+Verify connectivity:
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" cluster-info 2>/dev/null
+```
+
+If unreachable, ask the user for a valid kubeconfig path.
+
+### 1c. Ensure namespace exists on cluster
+
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" get ns "$NAMESPACE" 2>/dev/null
+```
+
+If namespace **exists**:
+- Check what's deployed: `kubectl --kubeconfig "$KUBECONFIG_PATH" get pods -n "$NAMESPACE" 2>/dev/null`
+- If pods are present, ask: "Namespace `$NAMESPACE` already has resources. Recreate it (delete and create fresh) or keep existing?"
+- If user wants to recreate: `kubectl delete ns "$NAMESPACE" && kubectl create ns "$NAMESPACE"`
+
+If namespace **does not exist**:
+- Create it: `kubectl --kubeconfig "$KUBECONFIG_PATH" create ns "$NAMESPACE"`
+
+### 1d. Modify workflow files
+
+For each discovered workflow file, add the branch to the `push.branches` array. Use the Edit tool — do NOT rewrite the entire file.
+
+Example: add `- "<branch>"` under `push.branches` alongside `- "main"`.
+
+### 1e. Modify pipeline config
+
+In the pipeline config file:
+- Set `productiveBranch` to the target branch name.
+- Set `namespace` (under `kubernetesDeploy` or equivalent) to the target namespace.
+
+### 1f. Commit and push
+
+Stage only the modified CI/CD files:
+```bash
+git add <workflow files> <pipeline config>
+git commit -m "ci: enable CI/CD deployment for branch $BRANCH to namespace $NAMESPACE"
+git push
+```
+
+If push fails (no upstream), set upstream:
+```bash
+git push --set-upstream origin "$BRANCH"
+```
+
+### 1g. Wait for deployment
+
+Print: `[cicd] Waiting for CI/CD pipeline to trigger and pods to appear...`
+
+Poll for pods in the namespace (up to 10 minutes, checking every 30s):
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" get pods -n "$NAMESPACE" --no-headers 2>/dev/null
+```
+
+Once pods appear, wait for them to become Ready:
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" wait --for=condition=Ready pods --all -n "$NAMESPACE" --timeout=300s
+```
+
+If timeout is reached, show pod status and logs of non-ready pods for debugging:
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" get pods -n "$NAMESPACE"
+kubectl --kubeconfig "$KUBECONFIG_PATH" describe pods -n "$NAMESPACE" --field-selector=status.phase!=Running
+```
+
+Print final status: `[cicd] Deployment complete. Pods in namespace $NAMESPACE:`
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" get pods -n "$NAMESPACE"
+```
+
+## PHASE 2 — Disable (Revert)
+
+### 2a. Identify changes to revert
+
+For each workflow file modified during enable:
+- Remove the branch from `push.branches`, leaving only `"main"` (or whatever was there originally).
+
+For the pipeline config:
+- Reset `productiveBranch` back to `"main"`.
+- Optionally reset `namespace` — ask: "Reset namespace in pipeline config back to its previous value, or leave as-is?"
+
+### 2b. Confirm with user
+
+Show a summary of changes that will be reverted. Ask: "Proceed with reverting CI/CD changes?"
+
+### 2c. Commit and push
+
+```bash
+git add <workflow files> <pipeline config>
+git commit -m "ci: disable CI/CD deployment for branch $BRANCH, revert to main-only"
+git push
+```
+
+Print: `[cicd] CI/CD deployment disabled. Branch triggers reverted to main-only.`
+
+</process>
+
+<guardrails>
+
+## Safety Rules
+
+- **Never force-delete namespaces without explicit user confirmation** — always ask first and show what's deployed.
+- **Never modify files beyond the CI/CD config files** — only workflow triggers and pipeline config.
+- **Never force-push** — always regular push. If push fails for reasons other than missing upstream, stop and inform.
+- **Always show the diff before committing** — let the user review the changes.
+- **Secrets**: never print kubeconfig contents, tokens, or credentials in output.
+- **Revert is always available**: if the user says "disable" or "revert" at any point during or after enable, switch to Phase 2.
+
+## Assumptions
+
+- The project uses GitHub Actions workflows with `push.branches` triggers.
+- There is a `.pipeline/config.yml` (or similar) with `productiveBranch` and `namespace` fields.
+- The user has `kubectl` access to the target cluster.
+- The user has git push access to the repository.
+
+If any assumption doesn't hold, inform the user and ask how to proceed.
+
+</guardrails>

+<objective>
+Conduct a rigorous, multi-perspective code review by assembling a council of expert agents — each reviewing from their professional discipline. The council operates like a real engineering review board: independent parallel analysis, followed by cross-referencing and synthesis into a single authoritative report.

+The skill thinks before it judges. Like GSD's goal-backward verification and OpenSpec's exploratory stance, this review first *understands the intent* behind the changes, then evaluates whether the implementation achieves that intent correctly, safely, and maintainably.

+**Three modes:**
+1. **Diff mode** (default): Review the current working tree changes
+2. **PR mode** (GitHub URL): Full PR lifecycle review — diff, commits, existing comments, rebase health

+## PHASE 0 — Thinking First (The OpenSpec Stance)
+
+Before reviewing, understand what you're looking at. This is not a mechanical checklist pass — it's critical thinking applied to code.
+
+Ask yourself:
+- **What is the author trying to achieve?** Read commit messages, PR description, changed file names.
+- **What is the blast radius?** How many modules does this touch? Could a change here break something elsewhere?
+- **What assumptions does this code make?** About state, about ordering, about availability.
+- **What would surprise a future reader?** That's where bugs and maintenance debt hide.
+
+This phase produces no output — it shapes how you brief each council member.

+## PHASE 1 — Input Resolution & Context Gathering
+
+### 1a. Determine mode and gather the diff
+
+**DIFF mode:**
+```bash
+REPO_ROOT=$(git rev-parse --show-toplevel)
+DIFF_STAT=$(git diff --stat HEAD)
+DIFF_CONTENT=$(git diff HEAD)
+# If no unstaged changes, check staged:
+if [ -z "$DIFF_CONTENT" ]; then
+  DIFF_CONTENT=$(git diff --cached)
+  DIFF_STAT=$(git diff --cached --stat)
+fi
+```
+
+**PR mode:**
+```bash
+# Fetch PR metadata
+PR_META=$(gh pr view $PR_NUMBER --json title,body,state,baseRefName,headRefName,commits,reviews,labels)
+PR_TITLE=$(echo "$PR_META" | jq -r '.title')
+PR_BODY=$(echo "$PR_META" | jq -r '.body')
+PR_BASE=$(echo "$PR_META" | jq -r '.baseRefName')
+PR_HEAD=$(echo "$PR_META" | jq -r '.headRefName')
+
+# Get the diff
+DIFF_CONTENT=$(gh pr diff $PR_NUMBER)
+DIFF_STAT=$(gh pr diff $PR_NUMBER --stat 2>/dev/null || echo "$DIFF_CONTENT" | diffstat)

+# Get all commits in the PR

+for candidate in "$REPO_ROOT/chart" "$REPO_ROOT/helm" "$REPO_ROOT/deploy/chart" "$REPO_ROOT/charts"; do

+On failure: print build output and stop.
+
+## PHASE 2 — Push
+
+### Strategy: Kyma in-cluster registry
+
+If `registry.type=kyma`:
+
+**2a. Ensure container runtime is ready**
+
+If podman:
+```bash
+podman machine list --format '{{.Name}} {{.Running}}'
+# Start if not running
+```
+
+**2b. Get Podman VM SSH details (if podman)**
+
+```bash
+PODMAN_PORT=$(podman machine inspect --format '{{.SSHConfig.Port}}')
+PODMAN_SSH_KEY=$(podman machine inspect --format '{{.SSHConfig.IdentityPath}}')
+PODMAN_USER=$(podman machine inspect --format '{{.SSHConfig.RemoteUsername}}')
+```
+
+**2c. Tag image**
+
+```bash
+PUSH_TAG="localhost:5001/$CHART_NAME:latest"
+$CONTAINER_RUNTIME tag "$LOCAL_TAG" "$PUSH_TAG"
+```
+
+**2d. Port-forward to registry**
+
+```bash
+kill $(lsof -ti:5001) 2>/dev/null || true
+kubectl --kubeconfig "$KUBECONFIG_PATH" \
+  -n docker-registry port-forward svc/dockerregistry 5001:${REG_SVC_PORT:-5000} --address 127.0.0.1 &
+PF_PID=$!
+sleep 3
+curl -sf http://localhost:5001/v2/ >/dev/null 2>&1 || { sleep 3; curl -sf http://localhost:5001/v2/ >/dev/null 2>&1; } || {
+  echo "[deploy] ERROR: Registry not reachable via port-forward"; kill $PF_PID 2>/dev/null; exit 1
+}
+```
+
+**2e. SSH reverse tunnel into Podman VM (if podman)**
+
+```bash
+ssh -o StrictHostKeyChecking=no \
+    -i "$PODMAN_SSH_KEY" \
+    -p "$PODMAN_PORT" \
+    -R 5001:127.0.0.1:5001 -N -f \
+    "$PODMAN_USER@localhost"
+sleep 2
+# Verify registry reachable from VM
+ssh -o StrictHostKeyChecking=no \
+    -i "$PODMAN_SSH_KEY" \
+    -p "$PODMAN_PORT" \
+    "$PODMAN_USER@localhost" "curl -sf http://127.0.0.1:5001/v2/" >/dev/null 2>&1
+```
+
+**2f. Extract registry credentials**
+
+```bash
+REG_SECRET=$(kubectl --kubeconfig "$KUBECONFIG_PATH" \
+  -n docker-registry get secret dockerregistry-config \
+  -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d)
+
+# Extract user:password from the auths for the pull address
+REG_USER=$(echo "$REG_SECRET" | python3 -c "
+import json, sys, base64
+d = json.load(sys.stdin)
+for host, auth in d.get('auths', {}).items():
+    u, p = base64.b64decode(auth['auth']).decode().split(':', 1)
+    print(u)
+    break
+")
+REG_PASS=$(echo "$REG_SECRET" | python3 -c "
+import json, sys, base64
+d = json.load(sys.stdin)
+for host, auth in d.get('auths', {}).items():
+    u, p = base64.b64decode(auth['auth']).decode().split(':', 1)
+    print(p)
+    break
+")
+```
+
+**2g. Login and push**
+
+If podman (push from inside VM):
+```bash
+ssh -o StrictHostKeyChecking=no \
+    -i "$PODMAN_SSH_KEY" \
+    -p "$PODMAN_PORT" \
+    "$PODMAN_USER@localhost" \
+    "podman login --tls-verify=false --username '$REG_USER' --password-stdin localhost:5001" <<< "$REG_PASS"
+
+ssh -o StrictHostKeyChecking=no \
+    -i "$PODMAN_SSH_KEY" \
+    -p "$PODMAN_PORT" \
+    "$PODMAN_USER@localhost" \
+    "podman push --tls-verify=false localhost:5001/$CHART_NAME:latest"
+```
+
+If docker (push directly):
+```bash
+echo "$REG_PASS" | docker login --username "$REG_USER" --password-stdin localhost:5001
+docker push "localhost:5001/$CHART_NAME:latest"
+```
+
+If push fails with `use of closed network connection`: kill port-forward, restart from 2d, retry once.
+
+**2h. Cleanup**
+
+```bash
+kill $PF_PID 2>/dev/null || true
+```
+
+Print: `[deploy] Push complete`
+
+### Strategy: Generic registry
+
+If `registry.type=generic`:
+```bash
+PUSH_TAG="$REGISTRY_PUSH_ADDRESS/$CHART_NAME:latest"
+$CONTAINER_RUNTIME tag "$LOCAL_TAG" "$PUSH_TAG"
+$CONTAINER_RUNTIME push "$PUSH_TAG"
+```
+
+## PHASE 3 — Deploy
+
+### 3a. Ensure namespace exists
+
+```bash
+kubectl --kubeconfig "$KUBECONFIG_PATH" get ns "$NAMESPACE" 2>/dev/null || \
+  kubectl --kubeconfig "$KUBECONFIG_PATH" create ns "$NAMESPACE"
+
+# Label for Istio if available
+if [ "$HAS_ISTIO" = "true" ]; then
+  kubectl --kubeconfig "$KUBECONFIG_PATH" label namespace "$NAMESPACE" istio-injection=enabled --overwrite
+fi
+```
+
+### 3b. Build helm --set flags dynamically
+
+Start with auto-resolved values:
+```bash
+SET_FLAGS=""
+SET_FLAGS="$SET_FLAGS --set image.repository=$REGISTRY_PULL_ADDRESS/$CHART_NAME"
+SET_FLAGS="$SET_FLAGS --set image.tag=latest"
+SET_FLAGS="$SET_FLAGS --set image.pullPolicy=Always"
+```
+
+Add registry pull secret (if Kyma registry):
+```bash
+if [ "$HAS_KYMA_REGISTRY" = "true" ]; then
+  REG_DOCKERCONFIGJSON=$(kubectl --kubeconfig "$KUBECONFIG_PATH" \
+    -n docker-registry get secret dockerregistry-config \
+    -o jsonpath='{.data.\.dockerconfigjson}')
+  SET_FLAGS="$SET_FLAGS --set secret.enabled=true"
+  SET_FLAGS="$SET_FLAGS --set-file secret.dockerconfigjson=<(echo $REG_DOCKERCONFIGJSON)"
+fi
+```
+
+Add cached values (from `.deploy-cache.yaml` helm.values section):
+```bash
+# For each key-value pair in helm.values:
+SET_FLAGS="$SET_FLAGS --set $KEY=$VALUE"
+```
+
+Add cluster-capability overrides:
+```bash
+if [ "$HAS_KYMA_APIRULE" = "false" ]; then
+  SET_FLAGS="$SET_FLAGS --set apirule.enabled=false"
+fi
+if [ "$HAS_BTP_OPERATOR" = "false" ]; then
+  SET_FLAGS="$SET_FLAGS --set database.serviceBinding.enabled=false"
+fi
+if [ "$HAS_EXTERNAL_SECRETS" = "false" ]; then
+  SET_FLAGS="$SET_FLAGS --set jaasVault.enabled=false"
+fi
+```
+
+Add namespace-scoped values (if chart has controller):
+```bash
+# If values.yaml has controller.watchNamespace
+SET_FLAGS="$SET_FLAGS --set controller.watchNamespace=$NAMESPACE"
+```
+
+### 3c. Dry-run mode
+
+If `PHASE=dry-run`:
+```bash
+echo "[deploy] DRY RUN — would execute:"
+echo ""
+echo "helm --kubeconfig $KUBECONFIG_PATH \\"
+echo "  upgrade --install $RELEASE_NAME \\"
+echo "  $CHART_PATH \\"
+echo "  -n $NAMESPACE \\"
+echo "  $SET_FLAGS \\"
+echo "  --timeout 10m --wait"
+echo ""
+echo "Rendering templates..."
+helm --kubeconfig "$KUBECONFIG_PATH" template "$RELEASE_NAME" "$CHART_PATH" -n "$NAMESPACE" $SET_FLAGS > /dev/null
+echo "[deploy] Template rendering: OK"
+```
+
+Print any template errors. Do NOT execute.
+
+### 3d. Helm upgrade
+
+```bash
+RELEASE_NAME="${CHART_NAME}"
+helm --kubeconfig "$KUBECONFIG_PATH" \
+  upgrade --install "$RELEASE_NAME" \
+  "$CHART_PATH" \
+  -n "$NAMESPACE" \
+  $SET_FLAGS \
+  --timeout 10m \
+  --wait
+```
+
+### 3e. Wait for rollouts
+
+Find all deployments created by this release:
+```bash
+DEPLOYMENTS=$(kubectl --kubeconfig "$KUBECONFIG_PATH" \
+  -n "$NAMESPACE" get deployments \
+  -l "app.kubernetes.io/instance=$RELEASE_NAME" \
+  -o jsonpath='{.items[*].metadata.name}')
+
+for DEP in $DEPLOYMENTS; do
+  kubectl --kubeconfig "$KUBECONFIG_PATH" \
+    -n "$NAMESPACE" rollout status "deployment/$DEP" --timeout=120s
+done
+```
+
+### 3f. Verify health (if external URL available)
+
+If `HAS_KYMA_APIRULE=true` and cache has `cluster.domain`:
+```bash
+# Determine health path from values.yaml probes section
+HEALTH_PATH=$(grep -A2 'liveness:' "$CHART_PATH/values.yaml" | grep 'path:' | awk '{print $2}' | head -1)
+HEALTH_PATH="${HEALTH_PATH:-/healthz}"
+
+# Determine the apirule host from chart values
+APIRULE_HOST=$(grep -A1 'apirule:' "$CHART_PATH/values.yaml" | grep 'host:' | awk '{print $2}')
+EXTERNAL_URL="https://${APIRULE_HOST}-${NAMESPACE}.${CLUSTER_DOMAIN}"
+
+# Retry up to 3 times (APIRule DNS propagation)
+for i in 1 2 3; do
+  if curl -sf "$EXTERNAL_URL$HEALTH_PATH" >/dev/null 2>&1; then
+    echo "[deploy] Health check passed: $EXTERNAL_URL$HEALTH_PATH"
+    break
+  fi
+  [ "$i" -lt 3 ] && sleep 10
+done
+```
+
+Print: `[deploy] Deploy complete — $EXTERNAL_URL`

+<troubleshooting>
+
+| Category | Symptom | Detection | Fix |
+|----------|---------|-----------|-----|
+| Build | `exec format error` in pod logs | Image arch != cluster arch | Ensure `--platform linux/amd64` when cluster is amd64 |
+| Build | Build fails | Non-zero exit | Print full output; check Dockerfile syntax |
+| Push | `authentication required` | Registry login failed | Re-extract credentials from registry secret |
+| Push | `connection refused` on port 5001 | Port-forward not running | Kill stale listeners, restart port-forward |
+| Push | `use of closed network connection` | Port-forward dropped mid-upload | Restart port-forward, retry push once |
+| Deploy | Helm template error | `helm upgrade` exits before applying | Run `helm template` to see which `required()` failed |
+| Deploy | Timeout on first deploy | BTP ServiceInstance provisioning (2-3 min) | Increase `--timeout`; check `kubectl get serviceinstance -n $NAMESPACE` |
+| Deploy | `no matches for kind "ServiceInstance"` | Chart enables BTP but cluster has no operator | Set `database.serviceBinding.enabled=false` |
+| Deploy | `no matches for kind "APIRule"` | Chart enables APIRule but no Kyma gateway | Set `apirule.enabled=false` |
+| Deploy | Rollout stuck | Pod CrashLoopBackOff or pending | `kubectl describe pod` + `kubectl logs` |
+| Verify | External URL returns 502/503 | Pod not ready or Istio not synced | Wait longer; check pod readiness |
+| Verify | DNS resolution failure | APIRule just created | Wait 30s for DNS propagation |
+
+</troubleshooting>
